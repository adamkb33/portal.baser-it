# Route Flattening Lost Routes Audit

Date: 2026-06-14

## Scope

Audit routes that became hard to find or effectively lost while flattening pages into the new template flow. This checks three things:

- Route tree registration in `app/lib/routing/**/routes.ts`.
- Expected `*.layout.tsx` and `*.route.tsx` files generated by `buildRoutesNested`.
- Practical reachability from navigation, setup warnings, route links, and root pages.

## Result

No registered UI or API route is missing its expected file. The loss is not a filesystem-registration problem. The loss is a reachability and route-ownership problem: some registered routes are placeholders, some important routes are nested too deeply for the current navigation model, and a few stale `ROUTES_MAP` references point to route IDs that no longer exist.

## Stale Route ID References

These route IDs were found in source but are not present in `ROUTES_MAP`:

- `booking.appointments`
- `company.contacts`
- `company.booking.profile.daily-schedule`
- `company.booking.appointments.create.existing-user` and `company.booking.appointments.create.new-user` are intentionally asserted as missing in a test.

API IDs such as `auth.user-status` and `company.booking.admin.service-groups.delete` are valid in `API_ROUTES_MAP`; those are not UI route issues.
