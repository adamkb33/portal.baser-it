# Public Booking Flow Simplification Plan

Date: 2026-08-22

Status: implemented and verified on 2026-08-22

## Why We Are Doing This

Customers have stopped on the contact or overview page because they believed the appointment was already booked.

That belief does not match the system state:

- Service, time, and contact choices only update the booking session.
- An SMS code verifies a mobile number; it does not book the appointment.
- The overview is the final review page.
- The appointment exists only after `submitAppointmentSession` succeeds and returns an `appointmentId`.

The flow must make this boundary obvious without adding a progress indicator, warning banner, or extra decision. The software should resolve identity and session state automatically. The customer should only provide missing information, review the result, and press one explicit final button.

Baymard observed users mistaking review pages for confirmation pages when the final action was not sufficiently clear. GOV.UK likewise recommends a clear review structure, contextual change actions, and a submit button that names the transaction. [Baymard](https://baymard.com/blog/office-depot-order-review-experience) · [GOV.UK](https://design-system.service.gov.uk/patterns/check-answers/)

## Decisions

1. Do not add a progress bar, stepper, dots, counter, or warning saying the appointment is not booked.
2. Do not add new shared UI components.
3. Keep the existing floating action dock on services, time, contact, and SMS.
4. Remove the floating action dock from the overview.
5. Delete the `CONTINUE_AS` and `RESUME` screens. Resolve both states automatically.
6. Use the existing attach, resume, and clear-user backend calls. No new backend endpoint is planned.
7. Use plain sections on the overview, not an outer card or receipt-style total block.
8. Use `Totalpris`, not `Estimert total`, unless the business later confirms that the displayed price can change.
9. Only the success page may state that the appointment is booked.

## Resulting Customer Path

`Tjenester → Tidspunkt → missing contact information only → SMS only when required → Oversikt → Bekreft timebestilling → Success`

- A signed-in customer with a verified number goes directly from time selection to the overview.
- A signed-in customer who needs mobile verification goes directly to SMS and then the overview.
- A customer without usable contact information sees the contact form.
- Account attachment, session resumption, and token refresh never become customer-facing screens.

## Screen 3 — Contact Resolution

Files:

- `app/routes/booking/public/appointment/session/contact/booking.public.appointment.session.contact.route.tsx`
- `app/routes/booking/public/appointment/session/contact/verify-mobile/booking.public.appointment.session.contact.verify-mobile.route.tsx`

### Automatic loader behavior

Remove `CONTINUE_AS` and `RESUME` from the rendered state union. Resolve contact state in this order:

1. If this booking session has an explicit manual-contact override, render `FORM` and do not attach the authenticated browser user.
2. If requirements return `DONE` with a session user, call the existing resume endpoint, set any returned auth cookies on the redirect, and redirect to the overview.
3. If `canAttachAuthenticatedUser` is true, call the existing attach endpoint before honoring an unfinished guest SMS challenge:
   - `DONE` → overview.
   - `VERIFY_MOBILE` → SMS verification.
4. If the remaining requirements return `VERIFY_MOBILE`, redirect to SMS verification.
5. Otherwise render `FORM`.
6. If automatic attach fails, render `FORM` with one concise error notice. Do not redirect back into the same resolver.

Loader-triggered attach and resume calls must tolerate revalidation and browser back/refresh without creating a redirect loop or corrupting the booking session.

### Manual contact override

The customer still needs one escape hatch for booking for another person or changing contact details:

- Render the overview's visible `Endre` control for `Kontakt` as a small POST form using the existing `intent=clear` action.
- After clearing the attached session user, redirect to `contact?form=1`.
- Record a manual-contact override for the current booking session so revisiting contact does not silently reattach the browser user.
- Clear that override after a valid contact submission or when the booking session changes.
- Keep the existing sign-in link inside the contact form.

Store the override in the existing server-side route session/cookie layer; do not add a backend endpoint solely for this flag.

### Contact form

- Caption: `Kontakt`
- H1: `Hvordan når vi deg?`
- Subtitle: `Etterpå får du se over alt før du bekrefter timebestillingen.`
- Keep `Fornavn`, `Etternavn`, `Mobilnummer`, and optional email.
- Mobile hint: `Vi sender en kode for å bekrefte nummeret.`
- Email hint: `Vi sender også timebekreftelsen på e-post etter bestilling.`
- Primary action: `Lagre og fortsett`.

`Lagre og fortsett` is intentional: a remembered verified number can skip SMS and go directly to the overview.

### SMS

- Caption: `SMS`
- H1: `Skriv inn SMS-koden`
- Subtitle: `Vi sendte en kode til {maskedMobile}. Etterpå får du se over alt før du bekrefter timebestillingen.`
- Primary action: `Bekreft mobilnummer`.
- Loading text: `Bekrefter mobilnummeret ...`
- Keep resend and change-number actions.

The SMS screen verifies the mobile number. It must never imply that entering the code books the appointment.

## Screen 4 — Overview

File: `app/routes/booking/public/appointment/session/overview/booking.public.appointment.session.overview.route.tsx`

### Header and summary

- Caption: `Oversikt`
- H1: `Stemmer alt?`
- Subtitle: `Se over detaljene før du bestiller timen.`
- Remove the outer rounded card.
- Render plain sections for `Tidspunkt`, `Kontakt`, `Behandler`, and `Tjenester`.
- Keep one contextual `Endre` control per section with a specific accessible label.
- Show price and duration as a plain `Totalpris` row inside `Tjenester`.
- Remove the highlighted receipt-style total block.

After a valid edit, return to the overview. If an edit invalidates a dependent choice, collect only what is missing before returning.

### Final action

- Remove `BookingFooterNav` from this page.
- Remove the secondary `Endre tid` action.
- Add this closing copy after the summary:
  - Heading: `Nå bestiller du timen`
  - Text: `Når du trykker Bekreft timebestilling, blir timen bestilt hos {companyName}.`
- Place one primary button directly after the copy: `Bekreft timebestilling`.
- Loading text: `Bekrefter timebestillingen ...`
- Keep double-submit prevention and existing submission-error recovery.

Nothing route-specific should appear after the final button. Successful `submitAppointmentSession` with a valid `appointmentId` remains the only route to the success page.

## Language Rules

- `time` means the appointment.
- `timebestilling` means the booking transaction.
- `SMS-kode` means the verification code.
- Before submission, `bekreft` must name what is being confirmed.
- Do not describe the appointment as booked before submission succeeds.
- `Timen er bestilt` is reserved for the terminal success state after a valid `appointmentId`.

## Non-Goals

- No progress UI.
- No new backend endpoint.
- No new shared UI component.
- No redesign of employee selection or the success page.
- No restyling of the floating dock on services, time, contact, or SMS.
- No warning banner or additional confirmation screen.
